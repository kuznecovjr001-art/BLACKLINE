# Подключение существующей игры к репозиторию — без потерь

Этот GitHub пока содержит документацию, а не пользовательские игровые исходники. Не генерируй проект-пустышку вместо уже созданной игры.

1. Сделай резервную копию локального Godot-проекта. Сверь реальный project.godot, версию Godot, состояние Git, addons, количество сцен, ресурсы.
2. Проверь, существует ли свой local git history. Не запускай git init/reset --hard и не переписывай историю в существующем рабочем каталоге вслепую.
3. После разрешения импортируй рабочие исходники в отдельную ветку GitHub; корневой project.godot должен остаться в корне проекта. Документацию слей без дублирования.
4. Не публикуй частные Drive-архивы, нелицензионные модели, платные исходные .blend, ключи доступа. Рассмотри Git LFS для больших законных ассетов, сначала оценив ограничения и стоимость.
5. Проведи Godot headless import / parse, запусти главную сцену, проверь плагины и input mappings. Фиксируй реальные ошибки и исполняемые тесты.
6. Получи ревью владельца и только потом объединяй ветку. Старый Unreal/Drive проект остаётся без изменений.
