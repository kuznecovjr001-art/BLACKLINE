# Архитектура Godot — модульная схема (инженерное предложение)

Схема данных:
GIS metadata/топология → чистый граф дорог/пешеходных путей → CityForge с отдельным визуальным asset_id → мир/этаж/помещение/объект с постоянным entity_id → активная симуляция → анимация/звук/HUD.

**Отделить:** geographic_feature_id, building_id, floor_id, room_id, door_id, entity_id, item_id, vehicle_id и visual_asset_id. Замена фасада не меняет состояние двери, лута или базы. Генерация процедурных интерьеров по стабильным seed и версиям; сохранение — дельты, без перегенерации обысканного лута.

Физика по бюджетам: около игрока столкновения, AI, анимации; средняя дистанция упрощена; дальние орды и инфраструктура моделируются агрегатами/событиями. Никаких тысяч физических NPC во всех восьми районах одновременно.

Рекомендуемые независимые области: WorldClock/Weather, CityGIS, CityForge/Interior, PlayerMotor, Combat/Animation, VehicleParts, ZombiePerception/Horde, Inventory/Loot, Crafting/UtilityGraph, BaseOwnership, Persistence/Networking, Presentation. Связь по контрактам/сигналам без гигантских autoloads и ссылок на пути узлов чужих сцен.

Система событий: пользовательские команды → проверка доступности/коллизии/прав → изменение авторитетного состояния → сохранение → визуальная/анимационная реакция. Урон не вычислять только по декоративной позе, линии прицеливания не проводить через непрозрачную игровую геометрию.

Сеть: в онлайне сервер подтверждает перемещение предметов, права, состояние машин и бой; офлайн использует общую логику, без обязательного подключения. Перед архитектурной миграцией обязательно фактически прочитать код пользователя.
